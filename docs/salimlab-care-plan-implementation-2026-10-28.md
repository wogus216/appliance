# 제품별 관리 일정표

작성일: 2026-10-28. 공개된 34개 정확 모델의 기술·관리 지도에서 관리 항목과 원문을 가져와, 날짜를 정하고 한 번의 달력 일정으로 저장하는 도구를 로컬 구현했다. 운영 배포 전이다.

## 사용 흐름

- 홈의 ‘가전 관리 일정표 만들기’ 또는 제품 상세의 ‘이 모델의 다음 관리 일정 만들기’로 진입한다. 제품 상세 링크는 모델 번호만 주소에 담아 정확 모델을 미리 선택한다.
- 관리 항목을 고른다. 설명서에 날짜 주기가 확인된 항목은 마지막 관리일로 다음 확인일을 계산한다. 구입일은 선택 입력이며 계산에 쓰지 않는다.
- 설명서에 고정 날짜가 없는 항목은 사용자가 확인일을 직접 정한다. 이 날짜를 제조사 관리 주기로 표시하지 않는다.
- 기준일이 지났다면 기준일을 그대로 보여 주고, 달력 파일에는 오늘 확인할 한 번의 일정으로 담는다. 관리했다면 사용자가 마지막 관리일을 갱신한다.
- `.ics` 달력 파일, 인쇄용 결과, 텍스트 복사를 제공한다. 달력 파일에 반복 규칙이나 알림을 넣지 않는다. 날짜·관리 이력은 URL·서버·브라우저 저장소에 남기지 않는다.

## 구현과 검증

- `src/lib/data/care-plan.ts`에서 공개 제품만 얇은 일정 데이터로 투영하고, 9개 주기를 정확 모델·항목 ID로 지정한다.
- `src/lib/care-plan.ts`에서 날짜 검증, 월말·윤년 계산, 관리 기록과 단일 종일 일정 `.ics`를 만든다. 달력 텍스트를 이스케이프하고 75바이트 줄 길이로 접는다.
- `src/components/tools/care-plan-tool.tsx`와 `/tools/care-plan` 정적 페이지에 모델·항목·날짜 선택, 근거, 결과·내보내기를 둔다. 홈·제품 지도·사이트맵에서 진입한다.
- 날짜·원문·달력 파일 집중 검사 10개와 실제 입력·내보내기 상호작용 검사 3개를 포함해 전체 테스트 **33개 파일·2,142개 통과**. TypeScript·변경 코드 ESLint·공백 검사 통과.
- 현재 작업 환경은 내부 포트 바인딩을 금지해 기본 Turbopack 빌드와 로컬 Chrome 실행이 거절됐다. 브라우저 도구의 로컬 파일 탐색도 자동 승인 정책이 ‘승인이 필요하지만 승인 정책은 never’라는 이유로 거절했다. 저장소에 설치된 Next.js의 webpack 경로로 **159개 페이지 정적 빌드**를 완료했다. 이 환경에서 실제 브라우저 조작·화면 캡처는 확인하지 못했다.
- 정적 산출물에서 34개 모델 선택지, 각 제품의 일정표 진입 링크 34개, 홈 링크, canonical, 사이트맵 경로를 대조했다.

실제 사용자가 일정 근거와 직접 정한 날짜를 구별하는지 검증하는 작업, 운영 배포는 남아 있다. 배포 시 사이트 수정일은 실제 배포일에 맞춰 갱신한다.
