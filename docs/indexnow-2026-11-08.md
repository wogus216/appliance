## 동작

- 키: `b18a7f9ac6b7d9b9b749703729e53f1c`, 공개 파일 `public/b18a7f9ac6b7d9b9b749703729e53f1c.txt`. 비밀이 아니다(프로토콜상 공개해야 검증된다). 로그인·서비스 계정 키와 무관하다.
- `.github/workflows/deploy.yml`: 빌드 뒤 **배포 직전 운영 사이트맵을 받아 두고**, `wrangler deploy` 뒤 `node scripts/indexnow.mjs --prev=<그 파일> --next=out/sitemap.xml`.
- 보내는 URL: 새 URL + lastmod가 바뀐 URL + 사이트맵에서 사라진 URL. lastmod는 `SITE_REVISIONS`(본문 변경일)에서 나오므로 본문이 안 바뀐 배포는 아무것도 보내지 않는다.
- 보내는 곳: `api.indexnow.org`(Bing 등) + `searchadvisor.naver.com/indexnow`. 공용 주소에서 네이버로 넘어가는지 확인하지 못해 네이버에도 직접 보낸다.
- 전송 전에 운영 키 파일이 키와 같은지 확인한다(최대 6회, 10초 간격). 다르면 보내지 않고 실패한다.
- HTTP 200(수신)·202(수신 후 키 검증 대기)만 성공으로 본다. 하나라도 실패하면 그 단계가 빨갛게 된다 — 이때도 배포는 이미 끝난 상태다.
- 배포 전 사이트맵 받기가 실패하면 배포는 그대로 진행하고 통지 단계가 파일 없음으로 실패한다.

### 알려진 빈틈

- `concurrency: cancel-in-progress`로 배포 직후·통지 전에 다음 푸시가 런을 취소하면 그 배포의 변경 URL은 통지되지 않는다(다음 런의 "배포 전 사이트맵"에 이미 반영돼 있어서). 그럴 때는 수동으로 보낸다.
- 다시 보내기: `node scripts/indexnow.mjs --urls=https://salimlab.kr/a,https://salimlab.kr/b` (조회만 하려면 `--dry-run`).
