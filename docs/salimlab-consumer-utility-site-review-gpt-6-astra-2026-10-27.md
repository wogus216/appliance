# 살림랩 소비자 실용 사이트 기획안 독립 검토

- 검토일: 2026-10-27

- 대상: [소비자 실용 사이트 기획안](salimlab-consumer-utility-site-plan-2026-10-27.md)과 검토 모델이 읽은 홈·상세 페이지, 전기량·가상 공간·세계 조사 문서

허용된 다섯 파일만 읽었습니다. 파일 수정과 외부 검색은 하지 않았습니다. 아래에서 코드로 확인한 사실, 문서에 기록된 주장, 제 판단을 구분합니다. 실제 트래픽·수익·공식 원문은 검증하지 않았습니다.

1. **[high] 첫 출시 순서가 기존 수요보다 보유 데이터에 끌려갑니다.**

   **근거:** 홈에는 “2026-09-16 네이버 클릭 상위 4개가 모두 에러코드 허브였다”는 [주석](/Users/kwonjaehyeon/Programming/sancho/appliance/src/app/page.tsx:39)이 있고, 실제 첫 화면도 오류코드 중심입니다. 이는 과거 분석 결과의 기록이며 현재 트래픽 비중을 증명하지는 않습니다. 반면 [전기량 기획](/Users/kwonjaehyeon/Programming/sancho/appliance/docs/appliance-energy-decision-feature-brief-2026-10-26.md:38)은 냉장고 4대를 먼저 만드는 이유로 자료의 풍부함을 듭니다.

   **손실:** 고장 때문에 온 방문자는 새 냉장고 두 모델의 전력량을 비교하려는 사람이 아닐 수 있습니다. 세 도구를 동시에 만들면 서로 다른 방문자 모집과 검증이 필요하고, 무엇이 성과를 냈는지도 흐려집니다.

   **교정:** 오류코드 행동 카드를 첫 후보로 올리되, 최근 실제 유입과 모델 대응 범위부터 확인하십시오. 냉장고 구매 도구는 별도의 수요 시험으로 분리해야 합니다. 홈 개편보다 유입이 발생하는 오류코드 페이지에서 실험하는 것이 먼저입니다.

2. **[high] 여덟 기능에는 공통 주제가 있지만 반복 사용의 연결고리가 없습니다.**

   **근거:** 구매·설치·고장·교체는 서로 다른 사건이고, 정기적 사용을 기대할 수 있는 기능은 관리 일정과 전력 기록입니다. 계획에는 오류코드 사용자에게 이 두 기능이 이어진다는 관찰이 없습니다. 달력 내보내기는 사이트 밖에서 일을 끝내는 기능이기도 합니다.

   **손실:** 한 번 잘 해결하고 떠난 사용자를 이탈로 해석하거나, 재방문을 만들려고 계정·알림·집 전체 관리 기능을 추가할 위험이 있습니다. 정수기 한 모델의 관리 카드는 기존 고장 방문자와 다른 고객군을 다시 모집해야 할 수도 있습니다.

   **교정:** 초기 제품 단위를 **“한 번의 가전 문제를 해결하는 서비스”**로 정의하십시오. 같은 고장으로 다시 방문한 것은 사건의 후속 이용이며, 다른 가전·다른 문제로 돌아온 것은 새로운 이용입니다. 둘을 구분해 측정해야 합니다. 반복 사용 제품으로 확장하는 결정은 후자의 증거가 나온 뒤에 하십시오.

   **근거:** 전기량은 공단 자료, 점검과 관리는 제조사 설명서, 설치 조건은 공식 설치 문서가 기반입니다. 출처 표시·도식·인쇄 카드 자체는 독자적 판단 가치를 입증하지 않습니다. 현재 제품 상세도 이미 근거와 비교 글을 연결합니다.

   **손실:** 공식 설명서를 보기 좋게 요약하는 데 편집 비용을 쓰면서, 사용자가 공식 안내 대신 살림랩을 선택할 이유는 남지 않을 수 있습니다.

   **교정:** 살아남을 가능성이 있는 가치는 다음 세 가지입니다.

   - 정확한 모델에 해당하는 문서를 찾는 수고를 줄이는 것.
   - 사용자의 조건과 여러 자료를 대조해 **결정을 막는 미확인 항목**을 찾는 것.
   - 기사·판매처·AS에 전달할 질문과 정보를 정리해 재문의를 줄이는 것.

   이는 아직 가설입니다. 제조사 안내를 이용하는 경우보다 **정확한 다음 행동까지 걸리는 시간, 잘못된 판단, 누락된 문의 정보**가 줄어드는지 비교해야 합니다. 가장 큰 독자적 가치가 교차 브랜드 설치 비교일 가능성도 있지만, 그만큼 검증 비용도 큽니다.

4. **[critical] 안전 관련 출처 규칙이 실제 게시 중단·정정 절차까지 이어지지 않습니다.**

   **근거:** 계획에는 정확 모델, 출처, 확인일, 안전 제한이 있습니다. 그러나 모델을 식별하지 못했을 때의 출력 범위, 문서 충돌의 처리 책임, 재검수 기한, 잘못된 카드의 회수·정정 방법은 없습니다. [공간 기획](/Users/kwonjaehyeon/Programming/sancho/appliance/docs/virtual-appliance-room-feature-brief-2026-10-26.md:9)에는 이미 설치 여유값의 충돌 사례가 기록돼 있습니다.

   **피해:** 다른 파생 모델의 점검 절차를 적용하거나, 오래된 서비스 정보를 따라 조치를 늦출 수 있습니다. 공유·인쇄된 카드는 원문을 고쳐도 이전 안내가 남습니다. 이는 현재 위해가 발생했다는 판단이 아니라 **출시 차단 조건이 필요한 위험**입니다.

   **교정:** 안전 카드에는 다음을 출시 조건으로 두십시오.

   - 모델 적용 범위를 확인하지 못하면 해당 모델용 점검 절차를 출력하지 않습니다.
   - 설명서 개정판·적용 모델·해당 구절과 편집 판단을 함께 보관합니다.
   - 충돌한 안전 지침은 임의로 하나를 선택하지 않고 관련 안내를 보류합니다.
   - 안전·서비스·보증 정보와 고정된 제품 치수에 서로 다른 재검수 기준을 둡니다.
   - 카드에 버전과 최신본 주소를 넣고, 정정 시 영향을 받는 카드를 식별합니다.

   모델명 입력은 사용자에게 새 부담이 됩니다. 형번을 찾는 안내와 식별 실패 시 공식 서비스로 이어지는 경로도 필요합니다.

   **교정:** 출력 약속을 **“공식 시험값의 비교와 해석 한계”**로 좁히십시오. 단위뿐 아니라 시험 기준과 비교 대상의 적절성도 확인해야 합니다. 원자료의 자릿수는 유지하되, 그 차이가 실제 절감이나 구매 우열을 입증한다고 표현하지 마십시오. 네 모델만 다룬다는 범위는 입력 전에 보여 주고, 지원하지 않는 모델 요청도 수요 자료로 기록하십시오.

   **손실:** 설명을 듣고 카드를 이해한 것을 시장 수요로 오인할 수 있습니다. 카드 완성·인쇄·AS 이동도 문제 해결의 증거는 아닙니다. 반대로 안전하게 해결돼 AS에 가지 않은 경우는 성공일 수 있습니다.

   **교정:** 구현 전에 사람이 직접 만든 카드로 대조 실험을 하십시오. 기존 페이지와 제조사 안내를 이용하는 조건보다 낫지 않으면 도구 개발을 중단해야 합니다. 만족도나 자신감보다 **정확한 행동과 실제 실행**을 먼저 평가하십시오.

8. **[high] SEO·AdSense에 관한 주의 문구는 있지만 사업의 성립 조건이 없습니다.**

   **근거:** 계획은 승인·색인 보장이 없다고 명시합니다. 코드에서는 내부 품질 판정에 따라 제품 페이지의 색인과 광고 스크립트 노출을 제어합니다. 이는 사이트의 자체 규칙이며 검색 유입이나 광고 수익의 검증은 아닙니다. 계획에는 검수 원가, 최신성 유지비, 방문당 수익 자료가 없습니다.

   **손실:** 문제를 빨리 해결하는 페이지가 유용하더라도 편집 비용을 회수하지 못할 수 있습니다. 사례 본문을 추가하고 대량 복제를 피하는 것만으로 검색 수요가 생기지는 않습니다. 모델·오류코드 조합을 넓힐수록 갱신 부담도 늘어납니다.

**구현 전에 전략을 반증할 핵심 실험은 ‘수동 행동 카드 대 기존 안내’ 비교입니다.**

다음 수치는 업계 기준이나 통계적 확증 기준이 아니라, 소규모 팀의 **사전 중단선 제안**입니다.

- 카드 조건에서 15명 중 12명 이상이 중대한 누락 없이 다음 행동을 정하고, 대조 조건보다 3명 이상 많아야 합니다.
- 48시간 안에 적절한 다음 행동을 실제 실행한 사람이 카드 조건에서 10명 이상이며, 대조 조건보다 3명 이상 많아야 합니다. 공식 안내에 따라 조치를 중단하거나 문의하는 것도 성공입니다.
- 카드가 유발한 위험한 행동이나 잘못된 안심이 한 건이라도 나오면 공개 확대를 중단합니다.
- 후속 응답이 없는 사람은 실행 성공으로 계산하지 않습니다.

수동으로 충분히 도와준 카드조차 기존 안내보다 낫지 않다면, 자동화에 투자할 근거가 약합니다. 통과하더라도 작은 표본이므로 제한 출시 근거로만 사용해야 합니다.

수정한 6주 순서는 다음과 같습니다.

| 주차 | 할 일 | Go / No-go 기준 |
|---|---|---|
| **1주** | 최근 28일 유입의 검색어·랜딩 페이지·절대 건수를 확인하고 첫 제품군 하나를 선택합니다. 실제 문의·사용 사례 20건으로 모델 식별과 공식 근거 확보 가능성을 조사합니다. 주간 운영 예산도 고정합니다. | 20건 중 최소 12건에서 모델과 적용 근거를 확보할 수 있어야 진행합니다. 실패하면 도구 제작 대신 모델 식별·자료 접근 문제부터 해결합니다. 분석 자료가 없으면 현재 트래픽 우위는 미확인으로 남깁니다. |
| **2주** | 해당 제품군의 수동 행동 카드와 채점 기준을 준비합니다. 기존의 5명 시험은 입력 부담·오해·안전 문제를 찾는 용도로 사용합니다. | 게시 대상 카드의 모델 적용 근거가 모두 확인되고, 중대한 안전 오류가 없어야 대조 실험으로 갑니다. 문서 충돌은 해결하거나 대상에서 명시적으로 제외합니다. |
| **3주** | 위 30명 대조 실험과 48시간 후속 확인을 수행합니다. 카드 제작 시간도 기록합니다. | 사전 중단선을 충족할 때만 구현합니다. 실패하면 카드 내용을 수정해 재검증하며, 일정 때문에 개발로 넘어가지 않습니다. 모집 실패는 수요 입증이 아닙니다. |
| **4주** | 통과한 한 경로만 최소 구현합니다. 기존 오류코드 유입 페이지에서 모델 확인 → 행동 카드 → 필요한 공식 안내로 연결합니다. | 새로운 사용자 5명이 도움 없이 완료하고, 근거 없는 지시·위험한 오해가 없어야 제한 공개합니다. 실패하면 공개하지 않습니다. |
| **5주** | 제한된 실제 유입에서 지원 불가율, 중도 이탈, 적절한 행동, 검수 시간을 관찰합니다. 공유·인쇄 수치는 보조 지표로 둡니다. | 실제 이용에서 효과가 재현되고 1주차 운영 예산 안에서 유지돼야 범위를 늘립니다. 수동 실험보다 결과가 크게 나빠지면 모델 입력·자료 범위를 먼저 수정합니다. |
| **6주** | 소비자 효용, 유지 비용, 사업성, 새로운 과제로의 재방문을 각각 판정합니다. | 효용과 운영성이 통과하면 같은 제품군 안에서 확대합니다. 수익 근거가 없으면 광고 사업 확대는 보류합니다. 새 과제가 생긴 추적 대상 10명 중 5명 이상이 별도 유도 없이 다시 이용하는 신호가 있을 때만 반복 사용 실험을 다음 단계로 엽니다. 관찰 기회가 부족하면 미검증이며, 계정·알림을 만들지 않습니다. |

6주 안에 관리 주기나 교체 주기의 반복 사용을 충분히 관찰하기는 어렵습니다. 따라서 마지막 재방문 기준을 통과해도 전체 사용자의 유지율이 입증됐다고 해석해서는 안 됩니다.

**보류할 작업**은 명확합니다.

- 냉장고 전기량 도구와 2D 설치 도면: 구매 예정자의 실제 요청을 수동 비교표·설치 확인표로 검증할 때까지 보류합니다.
- 정수기 기술 지도, 관리 일정, 전력 기록, 집 전체 관리, 계정·알림, 사진·3D: 초기 오류코드 경로와 별개의 수요·운영 검증이 필요합니다.
- 독립적인 수리·교체 계산기: 실제 견적 수집과 비용 항목 누락을 줄이는 질문부터 검증합니다. 남은 수명을 모르는 상태에서는 어느 선택이 경제적인지 확정할 수 없습니다.
- 홈 전체 개편과 모델별 페이지 확대: 첫 유입 경로의 효용과 유지 비용이 확인된 뒤로 미룹니다.
