# 제품 상세 페이지 섹션 재배열 설계

작성일: 2026-08-11
대상: `src/app/products/[slug]/page.tsx` 및 `src/components/detail/*`

## 배경

상세 페이지의 섹션 순서가 "구매자가 묻는 순서"가 아니라 "우리가 가진 데이터 순서"로 쌓여 있다. 정보 밀도가 높은 것부터 부가정보 순으로 배치돼 콘텐츠 제작자 시점에 가깝다.

현재 순서와 각 섹션이 답하는 구매자 질문:

| # | 섹션 | 답하는 질문 |
|---|---|---|
| 1 | Hero — 이미지·평점·가격·구매CTA·스펙뱃지 | 이게 그 물건 맞나 / 얼마인가 |
| 2 | 스펙 레이더 5축 | (비교 대상이 없어 사실상 없음) |
| 3 | 상세 리뷰 + 추천/비추천 | 뭐가 좋고 뭐가 별로인가 |
| 4 | 운영비 TCO + 에너지등급 (가전만) | 사고 나서 돈이 얼마 더 드나 |
| 5 | 소음 + 설치 적합성 RoomFit | 우리 집에 맞나 |
| 6 | 에러코드 | (이미 산 사람의 질문) |
| 7 | 사용자 리뷰 | 남들은 어떻대 |
| 8 | 구매처 | 어디서 사나 |
| 9 | 비슷한 제품 | 다른 선택지는 |

문제점 세 가지:

1. **이탈 방어가 늦다.** 가전 구매 이탈 사유(우리 집에 안 들어감 → 전기세 → 소음)를 죽이는 섹션이 4~5번에 있어, 독자가 근거를 읽기 전에 떠난다.
2. **결론이 뒤에 있다.** "그래서 살 만한가"에 답하는 추천/비추천이 심층 리뷰 뒤에 묻혀 있다.
3. **같은 질문에 답하는 내용이 흩어져 있다.** 가격이 4곳(Hero 가격 / TCO / 에너지등급 전기세 / 구매처), 스펙이 3곳(Hero 뱃지 / 레이더 / RoomFit techSpecs)에 분산.

## 결정 사항

- **1차 목표는 체류(애드센스)**, 제휴 전환이 아니다. 따라서 Hero의 `#purchase` 앵커 CTA는 본문 전체를 스킵시키므로 제거 대상.
- **배열은 "반론 제거 순서"** — 결론을 먼저 주고, 이탈 사유를 발생 순서대로 죽인다.
- **비가전(TV·무선이어폰)은 축을 치환**한다. 섹션을 생략하지 않고, 해당 카테고리의 실제 이탈 사유로 슬롯을 채운다.
- **스펙 레이더 동급 오버레이는 이번 범위에서 제외.** 라벨만 명확히 해 오해를 없앤다.

## 목표 배열

순서는 12개 카테고리 전부 동일하다. 다르게 가는 건 ③④⑤ 슬롯의 **내용**뿐이다.

| # | 섹션 | 죽이는 이탈 사유 | id |
|---|---|---|---|
| 1 | Hero — 식별 + 결론 신호 | "여긴 내 질문에 답 안 하네" | — |
| 2 | 총평 + 이런 분께 추천/비추천 | "그래서 살 만한가" | `verdict` |
| 3 | 슬롯 fit | "안 들어감 / 내 환경에 안 맞음" | `fit` |
| 4 | 슬롯 value | "돈이 더 든다 / 값어치를 못 한다" | `value` |
| 5 | 슬롯 risk | "시끄럽다 / 기대에 못 미친다" | `risk` |
| 6 | 성능 상세 — 심층리뷰·핵심기능·레이더·전체 스펙표 | "근거 없음" | `performance` |
| 7 | 사용자 리뷰 | "남들 평가는" | `user-reviews` |
| 8 | 구매처 | 전환 | `purchase` |
| 9 | 비슷한 제품 | 세션 내 회유 | — |
| 10 | 에러코드 *(구매 후 참고)* | — (SEO 자산) | `errorcodes` |

⑥이 ⑤보다 뒤인 것은 의도적이다. "근거"보다 "이탈 방어"를 앞세운 선택.

에러코드를 맨 끝으로 내리는 것은 SEO 손해 가능성이 있으나, 페이지 내 텍스트는 그대로 남고 위치만 내려가므로 영향은 제한적이라고 판단한다.

### 슬롯 내용

| 슬롯 | 가전 (65개) | TV (4개) | 무선이어폰 (5개) |
|---|---|---|---|
| fit | 우리 집에 맞나 — RoomFit·치수·설치 | 설치·공간 — 크기·무게·스탠드·특징 | 내 폰·용도에 맞나 — 코덱·블루투스·멀티포인트·방수 |
| value | 10년 총비용 — TCO + 에너지등급 | 가격 대비 가치 — priceAnalysis | 가격 대비 가치 — priceAnalysis |
| risk | 소음 — NoiseComparison | 화질·게임 성능 — 해상도·주사율·HDR·스마트OS | 착용감·배터리 — 배터리·무게·드라이버 |

## 아키텍처

### 파일 계획

**신규 5개** (`src/components/detail/`)

| 파일 | 내용 | 출처 |
|---|---|---|
| `verdict-section.tsx` | 총평카드 + 추천/비추천 + 에디터 분석 | `detailed-review.tsx` 앞부분 + `page.tsx` 인라인 그리드 |
| `fit-section.tsx` | 슬롯 fit | `room-fit-section.tsx`의 RoomFit 블록 |
| `value-section.tsx` | 슬롯 value | `TcoCalculator` + `EnergyGradeImpact` 래핑, 비가전은 신규 UI |
| `risk-section.tsx` | 슬롯 risk | `NoiseComparison` 래핑 |
| `performance-section.tsx` | 심층리뷰 + 핵심기능 + 레이더 + 전체 스펙표 | `detailed-review.tsx` 뒷부분 + `spec-radar` + `room-fit-section`의 스펙표 |

**수정 3개**

- `page.tsx` — 섹션 순서 재배열, TOC 항목·id 갱신
- `hero-section.tsx` — `#purchase` CTA 제거, `#verdict` 앵커로 교체, 가성비·가격대 승격
- `category-config.ts` — `SECTION_SLOTS` 추가

**삭제 2개** — 내용이 위 5개로 흡수됨

- `detailed-review.tsx`
- `room-fit-section.tsx`

세 컴포넌트(`DetailedReview`·`RoomFitSection`·`SpecRadar`) 모두 상세 페이지에서만 쓰이므로 재구성에 다른 페이지 영향이 없다.

### 결론(②)의 구성

1. 총평 카드 — 가성비 ★, 가격대, `description`
2. 이런 분께 추천 / 비추천 그리드 (현재 `page.tsx` 인라인)
3. 에디터 분석 (`editorComment`)

**순서 주의**: 현재 `detailed-review.tsx`는 에디터 분석이 총평 바로 뒤에 오지만, 여기서는 추천/비추천을 앞으로 당긴다. `editorComment`는 제품에 따라 10줄이 넘어(예: `sony-wf-1000xm5`) 이걸 먼저 놓으면 "결론 먼저"라는 이 섹션의 목적이 희석되기 때문이다. 짧고 스캔 가능한 추천/비추천이 먼저 오고, 긴 산문은 그 근거로 뒤따른다.

### 슬롯 선언

`category-config.ts`에 `CORE_AXES`와 같은 재라벨 패턴으로 추가한다.

```ts
export interface SlotConfig {
  title: string;
  /** 비가전: 이 슬롯으로 끌어올릴 extraSpecs 라벨 */
  liftLabels?: string[];
}

export const SECTION_SLOTS: Record<ApplianceCategory, {
  fit: SlotConfig;
  value: SlotConfig;
  risk: SlotConfig;
}>;
```

- 가전 10종은 `{ fit: '우리 집에 맞나', value: '10년 총비용', risk: '소음' }`. 전용 컴포넌트가 렌더하므로 `liftLabels` 불필요.
- TV·무선이어폰은 위 표대로 `liftLabels` 지정.

슬롯 컴포넌트는 `isTraditionalAppliance(category)`로 내부 분기한다. config가 컴포넌트를 지정하는 방식은 타입이 복잡해지므로 쓰지 않는다.

### 누락 방지 규칙

`liftLabels`는 문자열 화이트리스트인데 `extraSpecs` 라벨이 제품마다 제각각이다(LG 스탠바이미는 `'스탠드 포함 무게'`, 소니 이어폰은 `'무게'`). 화이트리스트로 필터링하면 조용히 누락된다.

**규칙: 어떤 라벨도 버리지 않는다.** `liftLabels`는 "위로 끌어올릴 것"만 지정하고, 뽑히지 않은 나머지 `extraSpecs`는 전부 ⑥ 성능 상세의 전체 스펙표에 남긴다. 오타나 신규 라벨이 생겨도 정보 손실이 구조적으로 불가능하다.

### Hero 변경

- `#purchase` 앵커 CTA를 `#verdict` "결론부터 보기"로 교체. 체류가 1차 목표이므로 아래로 유도한다.
- `priceAnalysis.valueRating`(가성비 ★)과 `priceTier`를 Hero 뱃지 줄로 승격. 현재는 ②까지 스크롤해야 보인다. 데이터 추가는 없다.

### 성능 상세(⑥)의 구성

세 덩어리를 이 순서로 담는다. 카테고리 무관하게 동일하다.

1. 심층 리뷰 섹션들 (`getDetailedReview(slug)`)
2. 핵심 기능 (`features`)
3. 스펙 레이더
4. **전체 스펙표** — `techSpecs`의 모든 필드 + `extraSpecs` 전량. 현재 `room-fit-section.tsx`의 "상세 기술 사양" 블록을 그대로 옮긴다. 가전·비가전 공통으로 렌더하며, ③⑤ 슬롯으로 끌어올린 항목도 여기 중복 표기해 누락을 원천 차단한다.

### 레이더 라벨

동급 오버레이 대신 제목·부제만 수정한다. 5축 점수가 절대평가인지 상대평가인지 독자가 알 수 없는 문제를 문구로 해소한다.

- 제목: "스펙 분석" → **"카테고리 내 상대 평가"**
- 부제 추가: **"같은 {카테고리} 제품들과 비교한 에디터 평가입니다. 10점 만점."**

레이더 자체의 축 구성은 건드리지 않는다. 가전은 기존대로 `CORE_AXES` 5축 + `powerConsumption`에서 파생한 '저전력' 축을 더한 6축, 비가전은 5축을 그대로 유지한다.

## 데이터 실사

| 필드 | 보유 | 영향 |
|---|---|---|
| `roomFit` | 가전 65/65 | ③ 항상 렌더 |
| `monthlyElectricityCost` | 가전 65/65 | ④ TCO 항상 렌더 |
| `errorCodes` | 가전 65/65 | ⑩ 항상 렌더 |
| `energyGrade` | 41/74 | ④의 에너지등급 블록만 조건부 (기존 로직 유지) |
| 심층리뷰 | 74/74 | ⑥ 항상 내용 있음 |
| `purchaseLinks` | 74/74 | ⑧ 항상 렌더 |

가전 65개는 빈 섹션이 발생하지 않는다.

**유일하게 새로 만드는 화면**은 비가전 9개의 ④ 슬롯이다. TCO가 없으므로 `priceAnalysis`로 대체한다 — 정가 대비 실거래가 차액, 가성비 ★, 가격대, 대안 제품 링크. 필요한 데이터는 이미 전부 존재한다.

## 리스크

**앵커 ID 변경.** `#spec`·`#review`·`#cost`·`#noise`·`#spec-detail` → `#verdict`·`#fit`·`#value`·`#risk`·`#performance`. `#purchase`·`#errorcodes`는 유지. grep 확인 결과 외부 참조는 `hero-section.tsx`의 `#purchase` 하나뿐이며 이는 교체 대상이므로, 실질적인 파급은 없다.

**구조화 데이터는 안전.** `ProductJsonLd`·`BreadcrumbJsonLd`는 페이지 최상단에 있고 섹션 순서와 무관하다.

**롤백.** 조립 지점이 `page.tsx` 하나이므로, 새 컴포넌트를 남겨둔 채 `page.tsx`만 되돌리면 원복된다.

## 검증

1. `npm run lint` → `npm test` → `npm run build` (74개 정적 생성 전부 성공)
2. 육안 4종
   - 가전 + 에너지등급 있음 — ④에 두 블록이 다 나오는지
   - 가전 + 에너지등급 없음(선풍기류) — ④가 TCO만으로 자연스러운지
   - TV 1개 — ③⑤ 슬롯이 `extraSpecs`로 채워지고, ⑥ 스펙표에 나머지가 남는지
   - 무선이어폰 1개 — ④ 신규 UI
3. 슬롯으로 끌어올린 라벨이 ⑥ 전체 스펙표에서 누락되지 않았는지 TV·이어폰 9개 전수 확인

## 범위 밖

- **스펙 레이더 동급 오버레이** — `similarProducts` 상위 2개를 레이더에 겹쳐 그려 비교 맥락을 부여하는 작업. 비교 대상 선정 로직 + SVG 다중 폴리곤 + 범례가 필요해 별도 작업으로 분리한다. 레이더 단독으로는 정보가 빈약하다는 문제는 이번 재배열 후에도 남는다.
- 섹션 내부 UI 리디자인 — 이번 작업은 순서·묶음 재편에 한정한다.
