# 기저귀 성분 사전 설계 — 육아 소모품 확장 사이클 A

작성일: 2026-08-12
대상: 신규 `/materials` 라우트 및 소재 데이터 레이어

## 배경

살림랩은 지금까지 생활가전 12개 카테고리를 다뤘다. 가전은 몇 년에 한 번 사는 물건이라, 방문자가 구매를 마치면 다시 올 이유가 없다. **소모품은 같은 사람이 매달 산다.** 육아 소모품은 기저귀·분유·물티슈를 합쳐 월 30~40만 원이 지속 지출되고, 기저귀와 분유만으로도 월 20만 원을 넘는다.

그중 기저귀가 재구매 빈도 1위다. 신생아는 하루 10~15개, 1~2개월은 15~20개를 쓴다.

시장은 출산율 하락에도 커지고 있다. 한국 기저귀 시장은 2024년 5억 7,300만 달러에서 2034년 7억 4,300만 달러로 전망된다(CAGR 3.90%). 유아용만 떼면 3억 7,000만 달러에 CAGR 4.20%로 더 빠르다. 아이 한 명당 지출이 늘고 있다는 뜻이다.

그리고 2023년 육아 소모품 물가상승률은 종이기저귀 6.9%, 분유 5%로 일반 소비자물가(3.9%)를 크게 웃돌았다. **가격이 일반 물가보다 빠르게 오르면 가격 비교 수요가 구조적으로 커진다.** 살림랩이 하는 일이 정확히 그것이다.

## 조사에서 확인한 사실

이 셋이 설계 전체를 규정한다.

### 1. 유아용 기저귀는 전성분 표시 의무가 없다

생리대는 의약외품이라 2017년 릴리안 파동 이후 전성분 표시가 의무화됐다. **유아용 일회용 기저귀는 다른 법을 탄다** — 「어린이제품 안전 특별법」 안전확인대상이자 「위생용품 관리법」 대상이며, 전성분 공개 의무가 없다.

따라서 "전성분을 파고든다"는 원래 구상은 **데이터가 존재하지 않아 성립하지 않는다.** 제조사가 자발적으로 공개한 것만 있고 수준은 제각각이다.

### 2. 대신 KC 안전확인 시험 항목이라는 공적 뼈대가 있다

기저귀는 KC 안전확인을 받으려면 정해진 유해물질 항목을 시험해야 한다.

| 항목 | 시험 기준 |
|---|---|
| 형광증백제 | — |
| pH | — |
| 폼알데하이드 | KS K 0611 |
| 염소화페놀류 | KS K 0733 |
| 아조염료(아릴아민) | KS K 0147 · 0734 |
| 아크릴산 단량체 | — |

인증·시험기관은 FITI시험연구원, KATRI 등이다.

이 6개는 공적 기준이라 서술 위험이 낮다. "이 제품에 X가 들었다"(입증 책임이 우리에게 있다)가 아니라 "규제는 이 6가지를 이렇게 검사한다"(사실 전달)가 되기 때문이다. 그리고 이것을 부모 언어로 정리한 곳이 없다.

### 3. 규제 6항목은 기저귀의 제조 방식에서 도출된다

SAP(고흡수성수지)는 원유에서 추출한 아크릴산에 가성소다를 중합해 만들며, 자기 무게의 200배 이상을 흡수한다. 중합이 완전하지 않으면 **아크릴산이 단량체로 잔류**한다 — 그래서 규제가 아크릴산 단량체를 검사한다.

| 규제 항목 | 어디서 유래하나 |
|---|---|
| 아크릴산 단량체 | 흡수층 SAP의 미반응 잔류물 |
| 형광증백제 | 부직포·펄프의 백색도 향상 첨가 |
| 폼알데하이드 | 접착제·가공 잔류 |
| 염소화페놀류 | 펄프 표백·방부 처리 |
| 아조염료(아릴아민) | 무늬 인쇄·염색 |
| pH | 피부 접촉면 전체 |

**이 매핑이 콘텐츠 전체의 설계 원리다.** 규제 항목은 임의로 정해진 것이 아니라 기저귀를 만드는 방식에서 나올 수 있는 것들이고, 부모가 알고 싶은 것도 정확히 그 지점이다. "SAP 유해한가?"의 답은 SAP 자체가 아니라 잔류 단량체가 관리 대상이라는 것이다.

## 결정 사항

- **독자는 세 상황에서 온다**: 구매 검토("성분 괜찮은 걸로 사고 싶다"), 불안 해소("뉴스 봤는데 우리 애 거 괜찮나"), 학습("SAP가 뭐지"). **문제 발생형(발진 원인 추적)은 의도적으로 제외한다** — 의학 서술 위험이 가장 크다.
- **편집 경계: 규제 기준 + 공개 성분.** KC 6항목을 부모 언어로 해설하고, 제조사가 공개한 성분만 정리하되 미공개는 미공개로 명시한다. **살림랩이 자체 안전 등급을 매기지 않는다.** 전성분 데이터가 없는 상태의 등급 부여는 근거 없는 판정이며 표시광고법·명예훼손 위험이 실질적이다.
- **기존 `Appliance` 모델을 재사용하지 않는다.** 아래 참조.
- **성분 사전(A)을 제품 DB(B)보다 먼저 낸다.**

### 왜 새 모델인가

가전과 기저귀의 결정적 차이는 성분이 아니라 **단위**다. 에어컨은 제품 하나가 단위지만 **기저귀는 제품×사이즈가 단위**다. 하나의 제품 라인이 사이즈 5종을 갖고, 사이즈마다 장 수도 가격도 장당 단가도 다르다. 같은 사이즈도 포장 단위에 따라 단가가 또 갈린다.

`Appliance` 타입은 이를 표현할 수 없다. 이미 TV·무선이어폰을 담느라 `powerConsumption`·`noise`를 재라벨해 쓰고 있는데, 소모품까지 넣으면 그 억지가 임계를 넘는다.

### 왜 사전이 제품보다 먼저인가

1. 성분 사전은 제품 데이터 없이 완결된다. KC 6항목이라는 공적 근거만으로 쓸 수 있다.
2. 검색 유입이 제품 페이지보다 빨리 붙는다("SAP 유해", "형광증백제 기저귀").
3. **B의 최대 리스크와 무관하게 지금 확정 가능하다.** B는 표본 조사 결과에 따라 설계가 갈린다.

## 전체 구조

| 사이클 | 무엇 | 답하는 니즈 |
|---|---|---|
| **A. 성분 사전** | 소재·규제항목별 페이지 + 층 구조 인덱스 | 학습 |
| **B. 제품 DB** | 기저귀 제품×사이즈, 장당 단가, 성분 구성, KC 정보 | 구매 검토 |
| **C. 양방향 연결** | 제품→성분 칩, 성분→해당 제품 목록, 공개율 집계 | 불안 해소 |

```
A 성분 사전  →  표본 조사  →  B 제품 DB  →  C 연결
                    ↑ B 설계를 여기서 확정
```

**이 스펙은 사이클 A만 확정한다.** B·C는 개요까지만 적고 표본 조사 후 각자의 스펙을 쓴다. 지금 B를 확정하면 모르는 것 위에 스키마를 세우게 된다.

# 사이클 A — 성분 사전

## 데이터 모델

소재와 규제 항목을 **하나의 모델에 담고 종류로 구분한다.** 형광증백제는 소재이면서 규제 항목이라, 둘로 쪼개면 중복된다.

```ts
/** 기저귀 층 구조에서의 역할 */
export type MaterialRole = '표면' | '확산' | '흡수' | '방수' | '결합' | '첨가';

export type MaterialKind = '소재' | '규제항목';

export interface Material {
  /** URL slug — /materials/[slug] */
  slug: string;
  /** 표기명 (예: '고흡수성수지(SAP)') */
  name: string;
  /** 검색·동의어 (예: ['폴리아크릴산나트륨', 'Super Absorbent Polymer']) */
  aliases: string[];
  kind: MaterialKind;
  /**
   * 이 물질이 속하거나 유래하는 층.
   * kind가 '소재'면 필수. '규제항목'은 유래 층이 특정될 때만 채운다
   * (형광증백제는 '첨가', 아크릴산 단량체는 '흡수', pH는 층이 없어 비움).
   */
  role?: MaterialRole;
  /** 이게 무엇인지 2~3문장 */
  what: string;
  /** 왜 기저귀에 쓰는지 / 왜 규제하는지 2~3문장 */
  whyUsed: string;
  /** 흔히 제기되는 우려와, 규제·시험 기준이 그에 대해 무엇을 정하고 있는지 */
  concern?: string;
  /** kind가 '규제항목'일 때 시험 기준 (예: 'KS K 0611') */
  testStandard?: string;
  /** 상호 참조 slug — sap ↔ acrylic-acid-monomer */
  related: string[];
  /** 근거 출처 URL */
  sources: string[];
  /** 마지막 검수 시점 'YYYY-MM' */
  updated: string;
}
```

`related`는 사이클 C에서 제품 참조가 붙을 자리의 씨앗이다.

`sources`는 필수다. 편집 경계가 "규제 기준 전달"인 이상, 근거 없는 문장이 들어가면 경계가 무너진다.

## 라우트

| 경로 | 내용 |
|---|---|
| `/materials` | 층 구조 다이어그램 + 소재/규제항목 목록 |
| `/materials/[slug]` | 개별 페이지 |

**`/baby` 밑이 아니라 최상위에 둔다.** 분유·물티슈가 오면 성분 사전을 공유하기 때문이다 — 부직포는 물티슈에도 쓰인다.

## 인덱스 페이지

층 구조 다이어그램이 중심이다. 텍스트 목록만으로는 "기저귀가 무엇으로 만들어졌나"가 잡히지 않고, 이 다이어그램 자체가 인용·공유될 자산이 된다.

```
표면층   부직포(폴리프로필렌)          ← 피부 직접 접촉
확산층   부직포 / 티슈
흡수층   플러프펄프 + SAP              ← 아크릴산 단량체 규제 지점
방수층   폴리에틸렌 필름 / 통기성 필름
부속     핫멜트 접착제 · 엘라스틱 · 흡수표시 잉크
첨가     로션 · 향료 · (형광증백제)
```

인라인 SVG로 직접 그린다. 외부 라이브러리 의존 없음.

## 콘텐츠 목록 — 15개

**소재 9개**

| slug | 이름 | role |
|---|---|---|
| `nonwoven` | 부직포(폴리프로필렌) | 표면 |
| `acquisition-layer` | 확산층(ADL) | 확산 |
| `fluff-pulp` | 플러프펄프 | 흡수 |
| `sap` | 고흡수성수지(SAP) | 흡수 |
| `pe-film` | 폴리에틸렌 필름 | 방수 |
| `breathable-film` | 통기성 필름 | 방수 |
| `hot-melt-adhesive` | 핫멜트 접착제 | 결합 |
| `elastic` | 엘라스틱(신축사) | 결합 |
| `wetness-indicator` | 흡수표시 잉크 | 첨가 |

**규제항목 6개**

| slug | 이름 | testStandard |
|---|---|---|
| `optical-brightener` | 형광증백제 | — |
| `ph` | pH | — |
| `formaldehyde` | 폼알데하이드 | KS K 0611 |
| `chlorinated-phenols` | 염소화페놀류 | KS K 0733 |
| `azo-dyes` | 아조염료(아릴아민) | KS K 0147 · 0734 |
| `acrylic-acid-monomer` | 아크릴산 단량체 | — |

확산층(ADL)은 그 자체가 원료명이 아니라 별도의 부직포·티슈로 만든 층이다. 그럼에도 페이지를 두는 이유는, 층 구조를 이해하려면 "왜 흡수층 위에 한 겹이 더 있나"에 답해야 하기 때문이다. `what`에서 이 점을 먼저 밝힌다.

로션·향료는 별도 페이지를 만들지 않는다. 제조사마다 구성이 달라 일반화된 서술이 불가능하고, `freeOf` 표기 대상으로 사이클 B에서 다루는 편이 정확하다. 테이프·벨크로도 같은 이유로 제외한다 — 규제 6항목과 직접 연결되지 않는다.

각 페이지는 `what` / `whyUsed` / `concern` 세 블록이라 얇지 않고, `related` 상호 참조로 엮여 thin content 판정을 피한다.

## 집필 방식

초고는 AI가 쓰고 사람이 검수한다. **문장마다 근거 출처를 달아** 검수 시 근거 없는 문장을 걸러낼 수 있게 한다. `sources` 필드가 그 장치다.

`concern` 블록에는 살림랩의 판정이 아니라 **규제·시험 기준이 무엇을 정하고 있는지**만 쓴다. 이 경계는 스펙의 결정 사항이며 집필 단계에서 협상 대상이 아니다.

## 검증

- `npm run lint` → `npm test` → `npm run build`
- 15개 페이지 + 인덱스가 모두 정적 생성되는지
- 데이터 무결성 테스트:
  - `related` 참조가 전부 실재하는 slug인지, 그리고 **양방향인지** (`sap.related`에 `acrylic-acid-monomer`가 있으면 그 반대도 있어야 한다 — 한쪽만 걸리면 성분 페이지에서 왕복이 끊긴다)
  - `sources`가 비어 있지 않은지 — 근거 없는 페이지는 편집 경계 위반이다
  - `kind === '소재'`면 `role`이 반드시 있는지
  - `testStandard`는 `kind === '규제항목'`에만 있는지
- 기존 74개 제품 페이지가 영향받지 않는지

# 사이클 B·C 개요 (확정 아님)

## B. 제품 DB

```ts
type ConsumableCategory = '기저귀';   // 분유·물티슈 추가 예정

interface Consumable {
  slug, brand, name, category;
  line?: string;          // '매직컴포트'
  form?: string;          // 밴드형 / 팬티형
  variants: Variant[];
  materials: MaterialUsage[];
  safety: SafetyInfo;
}

interface Variant {
  size: string;           // '3단계 M'
  weightRange?: string;   // '6~11kg'
  packCount: number;
  price: number;
  // 장당 단가는 파생 — 저장하지 않는다 (가격 변경 시 어긋난다)
}

interface MaterialUsage {
  materialSlug: string;
  layer: MaterialRole;
  disclosed: boolean;     // 제조사 공개 여부
  note?: string;
}

interface SafetyInfo {
  kcNumber?: string;
  freeOf?: string[];      // ['형광증백제', '향료']
}
```

**`disclosed`가 이 설계의 보험이다.** 표본 조사 결과 대부분이 미공개로 나와도, 이 필드 하나로 "어느 브랜드가 투명한가"라는 비교축이 성립한다. 데이터 부재가 콘텐츠 부재가 되지 않게 한다.

## C. 양방향 연결

- 제품 페이지 → 성분 칩 → `/materials/[slug]`
- 성분 페이지 → 이 소재를 쓰는 제품 목록 (빌드 타임 역인덱스)
- 성분 페이지에 공개율 집계: "수집한 N개 제품 중 M개만 이 소재를 공개합니다"

마지막 항목이 이 기획에서 가장 강한 한 줄이 될 수 있다. 판정 없이 사실만으로 성립하고, 현재 아무도 하지 않는다.

## 표본 조사 (B 착수 전)

대상 6개 브랜드: **하기스, 팸퍼스, 군, 보솜이, 마미포코, 네이처러브메레**

확인 항목:

1. 소재·성분을 어디까지 공개하나 (공식몰 상세페이지 기준)
2. KC 안전확인 신고번호를 표기하나 — 표기하면 `safetykorea.kr`에서 공적 검증이 가능하다
3. **사이즈별 체중 범위·장 수·가격이 확보되나** (장당 단가 계산의 전제)
4. "무형광·무향료" 같은 문구의 근거를 대나

**3번이 B의 진짜 급소다.** 성분은 미공개여도 `disclosed: false`로 콘텐츠가 되지만, 가격·장수가 없으면 비교표가 빈다.

# 범위 밖

- **문제 발생형 콘텐츠**(발진 원인 추적, 증상→성분 역추적) — 의학 서술 위험. 다루지 않는다.
- **자체 안전 등급** — 전성분 데이터가 없는 상태의 등급 부여는 근거 없는 판정이다.
- 분유·물티슈 — 성분 사전은 공유하도록 설계하되, 데이터와 라우트는 별도 사이클.
- 기존 가전 12개 카테고리의 구조 변경.
