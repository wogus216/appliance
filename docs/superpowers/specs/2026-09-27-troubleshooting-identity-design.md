## 결정 사항

1. **사이트가 먼저 말하는 것을 바꾼다.** 홈 첫 화면·전역 내비·소개가 "고장 났을 때 무엇을 확인할지"를
   먼저 말한다. 제품·가이드·블로그는 남기되 뒤로 보낸다.
2. **URL은 지우지 않는다 — 2026-12-31까지.** 삭제·301·noindex 전환을 하지 않고 **추가만** 한다.
   구글 판정이 URL 요동과 겹쳐 있다는 가설(위)이 맞다면 또 흔드는 것이 가장 비싸다.
   → 그래서 9/27 진단 보고에서 권했던 "기저귀 성분 사전 제거"는 **이 원칙과 충돌해 보류한다**(§범위 밖).
3. **근거 없는 점수는 화면에서 뺀다.** `basis: 'editor'` 축은 "편집팀 판단"이라고 정직하게 라벨을
   붙여도 정보가 아니다. 축을 빼면 종합 점수가 무너지는 카테고리가 있으므로 §1단계-④에서 선택지를 둔다.
4. **독자 화면에서 내부 운영 수치를 뺀다.** "그중 26개가 검색 색인 대상", "모델 번호를 확인하지 못한
   제품 40개" 같은 문장은 SEO 작업 기록이다. 독자에게 의미 있는 수치 — "공식 문서와 대조해 바로잡은
   코드 N건", "다루는 브랜드·제품군·코드 수" — 로 바꾼다. 숫자는 손으로 적지 않고 데이터에서 계산한다
   (손으로 적은 숫자가 데이터와 어긋난 사고가 세 번 있었다).
5. **저자 — 필명 "산초"(사용자 결정 2026-09-27).** 대조군의 차이 중 하나가 사람이 보이는 저자였다.
   실제 운영자를 일관된 필명으로 밝히고, **실제로 하는 일**("제조사 매뉴얼·FAQ를 대조해 코드별 조치를
   정리한다")을 적는다. **경력·체험을 지어내지 않는다.** "살림랩 편집팀" 68곳을 상수 하나로 모은 뒤 값을 바꾼다(§1단계-③).
6. **코드별 심층 페이지는 파일럿 3~5개로만 연다(2단계).** 8월에 254개를 통합한 이유(템플릿 얇은 페이지)를
   되풀이하지 않도록, 허브 카드에 담을 수 없는 내용이 있는 코드만 연다.

**경로: `/error-codes/{brand}/{category-slug}/{code}`.** 제품군을 경로에 넣는다 — 같은 코드가 제품군마다 뜻이
다르다는 것이 8월 통합 때 앵커를 포기한 이유였다(`public/_redirects` 주석). 그리고 옛 상세 URL
`/error-codes/:brand/:code`는 301 규칙이 걸려 있어 **같은 경로를 되살리면 301→200 전환(요동)이 된다.**
세 번째 세그먼트를 두면 그 규칙과 겹치지 않는다(Cloudflare `_redirects`의 `:placeholder`는 한 세그먼트만
매칭 — **추정, 배포 후 `curl -I`로 확인**).

**데이터 모델이 모자란다.** `ErrorCode`에는 코드 단위 출처 필드가 없고(`types/appliance.ts:84-90`),
제품군은 부모 제품에서 온다. 출처는 브랜드 단위(`error-code-editorial.ts`)뿐이고 그마저 Dyson·Haier·Winix는
기록이 없다. 심층 페이지는 **코드 단위 출처(발행처 2곳 이상)**를 요구하므로 파일럿 코드에 한해 별도 레코드를 둔다.

허브 카드는 그대로 두고 "자세히" 링크만 단다. 파일럿 결과(네이버 클릭이 허브에서 새 페이지로 옮겨 가는지,
합이 늘어나는지)를 본 뒤에 확장 여부를 정한다. 합이 늘지 않고 옮겨 가기만 하면 확장하지 않는다.
