# 도구 연결·측정·정리 — 2026-10-30

2026-10-30 도구 평가에서 나온 다섯 항목 중 A(연결)·B(측정)·C(정리)를 구현한 기록이다. D(치수 직접 입력)와 E(수리·교체 재설계)는 이벤트나 사용자 검증 결과가 나온 뒤 정한다. 도구의 효용은 아직 검증되지 않았다. 사용자 검증 상태는 [기록지](salimlab-consumer-tool-user-check-2026-10-29.md)를 따른다.

## A. 연결

- 머리말·모바일 메뉴·꼬리말에 `/tools`를 넣었다.
- 에러코드 페이지 12쪽(`/error-codes`, 브랜드 허브 8, 상세 3)에 「코드를 확인한 다음」 절을 넣었다(`src/components/error-codes/next-tools.tsx`).
  - 수리·교체 비교표는 모든 페이지에서 잇는다. 모델 제한이 없는 도구다.
  - 수첩·관리 일정표는 그 브랜드의 공개 제품이 있는 허브와 상세에서만 잇는다. 귀뚜라미·경동나비엔 허브에서 이으면 고를 모델이 없다.
- 브랜드 허브 맨 위에 그 절로 건너뛰는 링크를, 상담 기록 결과에 수리·교체 비교표 링크를 넣었다.

코드 블록마다 넣지 않은 이유: 카드가 70개라 같은 문장이 허브당 최대 25번 반복된다.

## B. 측정

### 이벤트 사양

| 항목 | 값 |
| --- | --- |
| 이벤트 이름 | `tool_result` |
| 파라미터 | `tool_name` 하나(`src/lib/analytics.ts`) |
| 전송 조건 | 운영 도메인에서만, 화면(마운트)당 한 번 |
| 보내지 않는 것 | 입력한 치수·금액·측정값·날짜. 함수 인자가 도구 이름뿐이라 실을 길이 없다 |

### 한계

- 입력 중간값으로도 결과가 나오면 한 번 센다(`7`을 친 순간 등). 결과를 읽었다는 뜻은 아니다.
- 광고 차단기를 쓰는 방문자는 잡히지 않는다.
- 이 이벤트는 도구가 쓰였는지만 말한다. 판단에 도움이 됐는지는 사용자 검증으로만 알 수 있다.
- 2026-10-30 현재 GA가 히트를 받는지는 운영자가 일반 브라우저의 실시간 보고서로 확인해야 한다(Aside가 gtag.js를 막는다).

### 보는 법

GA4 → 보고서 → 참여도 → 이벤트 → `tool_result`. 도구별로 보려면 탐색 분석에서 이벤트 이름 `tool_result`를 필터하고 측정기준을 「페이지 경로」로 둔다. `/tools/*`는 경로가 곧 도구이고, 행동 카드는 경로가 허브라 어느 허브에서 썼는지 보인다. 맞춤 측정기준 등록은 필요하지 않다.

## C. 정리

- `/tools` 카드: 여는 단추를 설명 앞으로 옮겼다. 답하는 질문과 지원 범위만 펼쳐 두고, 답하지 못하는 질문·값 종류·입력 보관은 펼침 안에 둔다(정적 HTML에는 남는다). 첫 문단은 할 수 있는 일부터 적는다.
- 값 종류 표시: 공식 자료·공식 시험값·사용자 실측·사용자 입력·계산값은 회색 글자로 줄였다. 확인 필요·예시값은 색 표시를 유지한다. 복사 기록의 `[공식 자료]` 태그는 그대로다.
- 설치 공간·식기세척기 확인표: 확인 필요 칸의 문장 앞에 붙던 「확인 필요 ·」를 화면에서 뺐다. 복사 기록의 문장은 표시 없이도 읽혀야 해서 그대로 둔다.
- 정수기 비용: 칸마다 적던 확인일을 입력 절 설명 한 줄로 모았다.

## 쿠쿠 허브 시험: 해결 문단 접기
