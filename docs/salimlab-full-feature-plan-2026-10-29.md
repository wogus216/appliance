## 2. 모든 단계에 적용하는 규칙

1. **원문 → 근거 파일 → 데이터 → 테스트 → 화면** 순서. 정확한 모델의 공식 원문을 받아 쪽·절·인용과 해시를 `research/evidence/<날짜>/`에 남긴 뒤에만 데이터에 넣는다. 다른 모델·계열의 문구는 쓰지 않는다(이번 DWA-81R0D 레벨러 사례).
2. **값의 종류 표시**: 공식 자료 · 공식 시험값 · 사용자 실측 · 사용자 입력 · 계산값 · 예시값 · 확인 필요(`src/lib/value-kind.ts`). 화면과 복사·인쇄 기록 모두.
3. **판정 금지 영역**: 설치 가능 여부, 남은 수명, 재고장 확률, 법적 위약금 확정, 근거 없는 전기요금. 확인 필요 값은 비교·판정에 쓰지 않는다.
4. **대량 템플릿 금지**: 새 페이지는 허브·도구가 주지 못하는 정보(모델별 분기, 계산 규칙, 측정법)가 있을 때만 연다. 모델명만 바꾼 페이지를 만들지 않는다.
5. **URL 변경 최소화**: 301·404·noindex를 여러 번 바꾼 이력이 색인 부진의 원인 후보다(인과 불명). 기존 URL은 지우지 않고 보강한다.
6. **안전**: 가스·전기·누수·냉매 관련 코드는 설명서가 허용한 확인과 사용 중지·서비스 연락 기준만 싣는다.
7. **각 단계 완료 조건**: 단위·UI 테스트, `tsc`, lint, `next build --webpack`, 정적 빌드 브라우저 확인(1440px·390px), `<main>` 대조로 `SITE_REVISIONS` 갱신, 배포 후 라이브 확인.

## 3. 단계별 계획

크기 표시: S(1회 작업 안), M(원문 조사 + 구현), L(여러 모델의 원문 조사가 큼).

### 1단계 — 에러코드 문제 해결 확장 (L, 최우선)

실제 사용자가 오는 곳이다. 네이버 클릭 대부분이 여기서 나온다.

- **행동 카드 5 → 78개 코드 전부 검토.** 각 코드에 모델 범위, 사용 중지 조건, 설명서가 허용한 사용자 확인 순서, 서비스 연락 기준, AS 접수 때 전달할 요약(복사)을 붙인다. 기존 대조 기록(10-02~10-26 감사 파일)을 1차 원문과 다시 맞춘다. 원문으로 조치를 확인할 수 없는 코드는 카드를 만들지 않고 "확인된 조치 없음 → 서비스 연락"으로 남긴다.
- **보일러 38개 코드(귀뚜라미 25, 경동나비엔 13)**는 가스 기기다. 재시작·점검 안내는 설명서 문구가 있을 때만, 나머지는 사용 중지·서비스 연락만.
- **상세 페이지는 조건부로 연다.** 네이버 검색어에서 클릭이 확인됐고(10-28: 로보락 추락방지 센서 10/36, 쿠쿠 식기세척기 E1 6/21·dr 5/17·E2 4/21, SK매직 식기세척기 F3 4/106) 모델별 의미 분기가 있는 코드만 상세 페이지를 만든다. 지금 상세 페이지는 3개다.
- **사이트에 없는 코드 검색어**(10-25 조사: 쿠쿠 E2, SK정수기 F01 등)는 정확한 모델 원문이 있을 때만 추가한다.
- **404 허브 4개(Coway·Dyson·Winix·Xiaomi)**: 해당 브랜드 제품 상세의 증상·관리 절로 301을 걸지, 404를 유지할지 정한다. 정적 배포에서 `public/_redirects`가 동작하는지 먼저 확인한다.
- 완료 기준: 78개 코드마다 카드 또는 "카드 없음 사유"가 있고, 각 카드가 근거 파일 줄과 연결된다.

### 2단계 — 도구를 읽을 수 있는 페이지로, `/tools` 모음 (M)

- **`/tools` 모음 페이지**: 도구마다 답하는 질문과 답하지 못하는 질문, 지원 모델 수, 값 종류 표시의 뜻. 홈의 과제 진입과 연결한다.
- **도구별 정적 설명 절**(JS 없이 HTML에 렌더): 이 도구가 쓰는 공식 자료와 범위, 계산식, 재는 방법, 예시 계산(예시값으로 표시), 자주 하는 오해, 원문 링크. 도구마다 내용이 다르다. 공통 문구를 복사해 채우지 않는다.
- **판단 카드 공유**: 개인 입력값은 주소에 넣지 않는 원칙을 유지한다. 모델·예시 장면처럼 개인정보가 아닌 값만 주소로 복원하고, 결과는 복사·파일·인쇄로 남긴다.
- **광고**: 도구 페이지에는 계속 광고 스크립트를 넣지 않는다(입력 버튼 근처 오클릭 위험). 승인 뒤 설명 절에만 검토한다.

### 4단계 — 전기: 비교 확대, 실측 기록 저장, 요금 계산 (M + M)

- **전기량 비교 확대**: 에어컨은 실내기·실외기 조합과 신고 항목이 같고 냉방 면적이 비슷한 모델끼리만 비교한다. 정수기 3개는 공단 품목 구분이 같은지 먼저 확인한다. 품목에 모델이 하나뿐인 제습기·공기청정기는 비교 대신 신고값 참고로만 둔다.
- **실측 전력 기록**: 공단 신고값 병치를 냉장고 4개에서 신고 kWh가 있는 모든 모델로 넓힌다. 여러 기기 기록을 브라우저에 저장하고 내보내기를 붙인다.
- **전기요금 계산(한전 주택용)**: 사용자가 넣은 가구 월 사용량과 기기 실측 kWh로 "추가 사용분의 요금 차이"를 계산한다. 누진 구간, 계절, 기본요금, 기후환경요금, 연료비조정요금, 부가세, 전력기반기금을 한전 1차 원문의 시행일과 함께 넣는다. **출시 조건**: 한전 공식 요금 계산기와 3개 사례에서 같은 결과가 나와야 한다. 맞추지 못하면 내지 않는다.

### 5단계 — 비용 도구 (L)

- **정수기 렌탈·구매 총비용**(3개 모델): 월 렌탈료, 의무사용기간, 등록비, 방문관리 주기, 소유권 이전, 구매가와 필터비. 공식 판매 페이지 값은 확인일과 함께 기본값으로만 쓰고, 사용자가 자기 계약서 값으로 바꾼다. 중도해지 비용은 계약서와 공정위 기준의 계산식만 보여 주고 금액을 확정하지 않는다.
- **필터·소모품 연간 비용**: 공식 품번·가격·교체 주기가 모두 확인된 항목만 계산한다(관리 일정의 주기 확인 9개 항목에서 출발).

가격은 자주 바뀐다. 확인일이 90일을 넘으면 화면에 "가격 재확인 필요"를 띄우는 테스트를 둔다.

### 6단계 — 우리 집 가전 수첩 (M)

- 집 전체 관리 목록을 확장해 모델·구입일·보증 만료일(사용자 입력)·수리 기록·관리 기록을 한곳에 둔다. 서버 없이 브라우저 저장, JSON 내보내기·불러오기, 인쇄.
- **공식 기준 연결**: 소비자분쟁해결기준(공정위 고시)의 품목별 품질보증기간·부품보유기간을 원문 시행일과 함께 넣고, 구입일에서 계산한 "부품 보유기간 끝나는 날"(계산값)을 수리·교체 비교표와 연결한다. 실제 부품 재고는 제조사에 확인하라고 표시한다.

### 7단계 — 가상 공간 (S~M, 조건부)

- 냉장고 4개 도면에서 문짝 폭·경첩 위치를 판독해, 계산한 90° 개방 깊이가 설명서 값과 ±10mm 안에서 맞는 모델만 문 궤적을 그린다.
- 3단계에서 문 개방 치수가 확인된 세탁기·식기세척기에도 같은 평면도를 붙인다.

### 8단계 — 사이트 정리와 재심사 준비 (M)

- 소개·편집 원칙·평가 방법에 도구의 계산 규칙과 값 종류 표시를 반영한다. 현재형 광고 문구 같은 사실 불일치를 다시 점검한다.
- 색인 대상 전 페이지 표본 검수: 사양 반복만 있는 페이지가 남았는지 본다.
- 내부 링크 깨짐 0, 사이트맵의 모든 URL 200, 404로 가는 내부 링크 0을 테스트로 고정한다.
- 정정 기록·`SITE_REVISIONS`를 마무리하고 아래 재심사 조건을 점검한다.

### 병행 — 실제 사용자 검증

`docs/salimlab-consumer-tool-user-check-2026-10-29.md`대로 진행한다. 참가자 모집은 사용자가 맡는다. 결과가 나오면 같은 오해가 2명 이상 반복된 문구부터 고친다. 애드센스 안내의 "실제 사용자 관심"과 직접 닿는 유일한 근거다.

| 계정·알림 | 서버 없는 정적 배포라 저장·발송에 별도 백엔드가 필요하다. 구조 변경이 커서 재심사 전에 넣지 않는다. 대신 달력 파일과 JSON 내보내기를 쓴다. |
| 집 기준 냉방 계획 | 한국 주거 유형별 공식 근거 조사가 없다. 4단계의 요금 계산을 마친 뒤 별도 조사로 판단한다. |
| 전기 안전 독립 페이지 | 각 도구 안에 공식 주의 문구(접지, 멀티탭, 정격)를 넣는 것으로 대신한다. |

## 5. 순서·배포·재심사 시점

1. 1단계 → 2단계를 먼저 한다. 사용자가 실제로 오는 곳과 크롤러가 읽는 본문을 같이 키운다.
2. 3·4·5·6단계는 원문 조사 결과에 따라 순서를 바꿀 수 있다. 조사에서 원문이 안 나오는 모델은 "확인 필요"로 두고 다음으로 넘어간다.
3. **배포는 단계마다 한다.** 지금은 심사 중이 아니라 구조 변경 제한이 없다. 단계마다 테스트·라이브 확인 기록을 남긴다.
4. **재심사 요청 조건**(모두 충족 후 사용자가 버튼을 누른다):
   - 1·2·8단계 완료와 라이브 확인
   - 사이트맵 전 URL 200, 내부 404 링크 0, 공개 도구·카드의 근거 파일 연결 100%
   - 마지막 구조 변경 배포 뒤 재심사 요청까지 구조를 바꾸지 않을 것
   - 구글 색인 조건은 결정 사항(아래 3번)

## 6. 결정이 필요한 것

1. **단계 순서**: 위 순서(1→2→3~6→7→8)로 진행해도 되는가.
2. **TV·이어폰 9개 제품**: 권장은 그대로 유지다(이미 기술·관리 지도 반영, URL 변경 이력 위험). 다른 선택지는 홈 노출 축소, 또는 noindex.
3. **재심사와 구글 색인**: 10-25 기록에는 "다음 검토 요청은 색인이 움직인 뒤 판단"이라고 적혀 있다. 이번에도 그 조건을 둘지, 8단계가 끝나면 색인과 무관하게 요청할지.
4. **자주 바뀌는 값**(렌탈료·필터 가격·전기요금표) 게시: 확인일과 재확인 경고를 붙여 게시해도 되는가.
5. **404 허브 4개**: 제품 상세로 301(권장, 네이버 클릭 회수) 또는 404 유지.
