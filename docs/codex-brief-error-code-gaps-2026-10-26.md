## 2. 작업 ① — 빠진 코드 4개 보강

각 코드마다 순서대로 한다.

1. **공식 출처를 찾는다.** 제조사 사용설명서·공식 FAQ·고객센터 공지만 쓴다. 블로그·집계 사이트·콘텐츠팜의 값은 근거로 쓰지 않는다(검색 엔진이 콘텐츠팜을 물어온다). 기존 SK매직 FAQ 수집 도구(`scripts/collect-skmagic-faq.mjs`)와 기존 수집 문서가 쓰는 출처 표기 방식을 따른다.
2. **공식 출처에서 확인된 코드만 추가한다.** 의미, 원인, 이용자가 직접 할 수 있는 조치, 서비스센터를 불러야 하는 경우를 쓴다. 출처에 없는 조치·부품명·전화번호를 지어내지 않는다. 기존 코드 항목의 스키마·문체·출처 필드를 그대로 따른다.
3. **출처를 못 찾았거나 출처가 모호하면 추가하지 않는다.** 그 코드는 "불명"으로 보고서에 남긴다. 추정으로 메우지 않는다.
4. 전체 PDF나 긴 원문을 옮겨 싣지 않는다(요지와 출처 링크만).
5. SK정수기 F01은 SK매직 허브에 정수기 제품군이 없다는 점이 문제다. 공식 출처에 코드가 있어도 제품군 신설이 필요하면 **추가하지 말고 보고만** 한다(구조 변경은 별도 승인).

"F9"(식기세척기)는 같은 방법으로 공식 출처가 있는지만 조사하고, 있으면 ①과 같이 처리한다.

### 구현·검증 (코드를 추가한 경우에만)

- 값·상수를 바꾸기 전에 관련 문자열·타입을 전수검색해 영향 목록을 만든다.
- `SITE_REVISIONS`(`src/lib/data/site-revisions.ts`)에 오늘 날짜 항목을 추가한다. 경로는 추측하지 말고 `scripts/changed-pages.mjs`로 **배포된 빌드(`eb7bf74`)와 새 빌드의 `<main>` 본문을 대조**해 실제로 바뀐 사이트맵 경로만 적는다. 새로 생긴 페이지는 자기 검수일을 쓰므로 넣지 않는다. 대조 결과는 `research/evidence/<날짜>/changed-sitemap-vs-deployed.txt`에 남긴다.
- `src/lib/__tests__/site-revisions.test.ts`의 `LATEST_EXPECTED_LASTMOD`를 맞춘다(현재 `2026-10-26`).
- 기준 빌드를 별도 worktree에서 만들 때 `node_modules`를 심볼릭 링크하면 Turbopack이 거부한다. `cp -Rc`로 복제한다.
- 통과 기준: `npx tsc --noEmit`, `npx eslint src`, `npm run build`, `npx vitest run`이 모두 통과(직전 기준 25파일·1,948건). 통과한 명령과 수치를 보고서에 적는다.
- 빌드 산출물에서 새 코드가 실제로 본문에 있는지, 대조군(쿠쿠 E1 등)이 계속 있는지 같은 방법으로 확인한다.

## 3. 작업 ② — 코웨이 허브 복구 가능성 조사 (조사·보고만)

- 코웨이 공식 자료(사용설명서·공식 FAQ·고객센터)에서 정수기·공기청정기·비데 등의 에러코드 목록을 찾는다.
- 현재 카탈로그에서 코웨이 제품이 몇 개이고 각각 어떤 에러코드 데이터를 갖는지, 왜 허브가 만들어지지 않는지(`src/lib/error-codes.ts`) 파악한다.
- 보고할 것: 공식 출처가 있는 코드 수와 출처 목록, 허브를 만들려면 필요한 작업량(추가할 데이터·코드 변경), 이전 기록(`docs/f25-coway-release-check-2026-10-02.md` 등)에서 코웨이 코드를 뺀 이유가 있는지. **코드는 수정하지 않는다.**
- 다이슨·위닉스·샤오미는 이번 범위가 아니다. 조사 중 우연히 알게 된 것만 한 줄로 적는다.

## 4. 규칙

- 모르는 것은 "불명"이라고 쓰고 추정으로 메우지 않는다. 검증하지 못한 것에는 `추정:`을 붙인다.
- "없다"고 말하기 전에 대조군으로 도구가 살아있는지 확인한다(0건이면 반드시 잡혀야 할 것으로 한 번 더 돌린다).
- 집계 사이트·블로그의 날짜·수치는 1차 소스로 대조한다.
- 내부 품질 게이트 통과를 Google 색인이나 AdSense 승인으로 표현하지 않는다. 배포되지 않은 작업을 배포 완료로 기록하지 않는다.
- API 키·쿠키·로그인 정보를 문서·사이트·보고서·저장소에 넣지 않는다.
- 커밋 메시지에 AI 작성 표시 문구를 넣지 않는다.
- `main`에 직접 푸시하지 않는다. 작업 브랜치에 커밋하고 멈춘다. 푸시·배포는 사용자 승인 뒤에 한다.
- 이 저장소에는 다른 작업이 진행 중일 수 있다. 관련 없는 파일을 수정하지 않는다.
