생활 관리 담당자 관점 병렬 점검 — 2026-11-01

범위와 방법
가상 생활 과제로 달력 파일과 수첩의 관계, 전력 측정 기간 비교의 유용성을 점검한다.
실제 외부 사람 조사, 실제 계량기 측정, 실제 캘린더 앱 등록/알림은 이번 과제에 포함하지 않는다.
기존 기록을 보존하고 평가용 항목만 정리한다. 앱 소스는 수정하지 않는다.

준비 단계의 코드 관찰
1. 달력 파일
src/lib/care-plan.ts의 carePlanIcs는 VERSION:2.0, 단일 VEVENT, 종일 DTSTART;VALUE=DATE,
다음 날을 끝으로 하는 DTEND;VALUE=DATE, UTC DTSTAMP, 근거 설명과 제품 링크를 출력한다.
RRULE과 VALARM, 외부 달력 구독 주소는 없다. 한국어 줄은 UTF-8 75바이트 이하로 접고 CRLF를 사용한다.
src/components/tools/care-plan-tool.tsx의 saveCalendar는 클릭마다 새 난수 UID를 만든다.
따라서 새 파일은 같은 모델·항목·날짜라도 앞 파일과 UID가 다르며 기존 이벤트 갱신을 보장하지 않는다.
기존 파일을 이미 가져온 경우 중복/변경 처리는 캘린더 앱에서 따로 확인해야 한다.
종일 날짜는 시간대가 붙은 시각이 아니고 DTSTAMP만 UTC다. 실제 앱의 날짜 표시와 가져오기 처리는 미검증이다.

UI 텍스트 코드 관찰: 결과에 '한 번만 저장', '.ics 형식이며 반복 알림을 만들지 않습니다'가 있다.
가이드는 '관리한 뒤에는 새 마지막 관리일로 일정을 다시 만듭니다'라고 한다.
수첩에는 계정 동기화·알림 미지원 안내가 있으나, 이미 가져온 달력 일정은 수첩 날짜 수정으로 바뀌지 않는다는
설명과 재다운로드 시 중복 가능성 설명은 다운로드 버튼 근처에서 찾기 어렵다.

2. 전력 기록
src/lib/home-energy-record.ts의 저장 형식은 기록일 recordedAt, 기기명, 누적kWh, 측정일수, 30일환산값,
선택한 모델의 신고값, 선택한 추가요금 가정을 보관한다.
실제 측정 시작일·종료일·실내온도·설정온도·사용횟수·환경 메모는 입력/보관하지 않는다.
기록 모드의 recordedAt는 저장한 당일이어서 오래된 측정을 나중에 입력하면 측정 시기를 복원할 수 없다.
목록은 역순 카드로 값들을 보여 주므로 사람이 두 환산값을 눈으로 비교할 수 있다.
동일 기기 필터·측정기간별 자동 차이·그래프·계절 추이는 없다.
상단은 계절/설정에 따라 달라진다는 한계를 설명하지만 조건 자체를 남길 곳은 없다.

추가 문구 불일치(P2)
src/components/tools/guides/home-energy-guide.tsx 자주 하는 오해에는
'고지서의 가구 사용량을 함께 넣으면 아래 요금 차이 계산을 쓸 수 있습니다'라고 한다.
이는 최신 본문의 '기기분이 포함되지 않은 가구 사용량' 조건을 빠뜨린다.
기존 고지서에 이미 포함된 기기 사용분을 다시 더하지 않도록 하단 가이드도 조건을 일치시킬 필요가 있다.

7일8.4kWh →30일36.00kWh. 측정기간을 맞춘 환산 비교는 6.00kWh 차이지만
환경/기간이 달라 소비전력 개선·고장·절약 효과로 판정하지 않는다.
UI/실물 파일 수행 결과는 아래에 별도 기록한다.

이번 수행 상태
Aside guide, guide repl, skills list를 읽었으며 적용할 별도 서비스 스킬은 없었다.

이후 진행자가 같은 주소의 정적 서버를 준비하여 아래 실제 UI 과제를 완료했다.
초기 연결 실패를 앱 결함으로 집계하지 않았다.

실제 UI / 전력 기간 비교
측정한 기기 '병렬평가용-기간비교', 신고값 모델 RF85C90D1AP, 기존 기기 기록 모드를 선택했다.
1일1.4kWh를 입력해42.00kWh를 확인하고 저장했다. 다음으로7일8.4kWh를 넣어36.00kWh를 저장했다.
저장 목록2개에서 두 측정기간·누적량·30일환산값·같은 모델 신고값41.38kWh/월을 함께 읽을 수 있었다.
새로고침 후에도2개가 유지됐다. 두 카드의 이름과 기록일은 모두 동일한 '병렬평가용-기간비교 · 2026-11-01'이었다.
육안으로42.00과36.00을 비교하는 과제는 가능하다. 기간이 다른 원래 누적량1.4와8.4를 직접 비교하는 실수를 줄인다.
그러나 측정시작일·종료일·설정·실내조건·메모 입력이나 비교 그래프는 없고 기록모드에는 측정월도 없다.
6.00kWh 차이는 단순환산의 차이이며 절약/고장/개선 효과라는 결론은 내리지 않았다.
본인 이름의 삭제 버튼으로 두 건을 각각 삭제했고 저장목록0개를 확인했다. 기존 기록은0개였으며 다른기록을 수정하지 않았다.

실제 UI / 달력 파일과 수첩
WF24A9500KE 배수필터청소, 마지막관리2026-10-30 → 확인일2026-11-06을 화면에서 확인했다.
'달력 파일 저장'을 두 번 눌러 .ics와 (1).ics라는 두 다운로드 완료를 확인하고 파일을 읽었다.
두 번째 download.path를 읽은 내용은 첫 파일과 UID/DTSTAMP까지 동일했으므로 파일경로 재사용/다운로드 이벤트
관측 문제가 있을 수 있다. 따라서 이 두 건만으로 실제 재다운로드 UID 동일/상이 여부를 확정하지 않는다.
코드에서 클릭마다 새 난수UID를 생성한다는 사실과 실제 두 파일의 독립 비교를 구분한다.
다음 독립세션에서 다시 다운로드한 파일은 UID920360ea7c3a78ef1e465994897e71f4@salimlab.kr,
DTSTAMP20261101T110426Z, DTSTART;VALUE=DATE:20261106, DTEND;VALUE=DATE:20261107이었다.
VERSION2.0·단일VEVENT·설명서와원문링크·CRLF·한국어접기 확인. RRULE/VALARM은 없었다.
실제 캘린더 앱에 가져오거나 사용자 캘린더를 변경하지 않았다. 가져오기 성공·실제 알림·앱별중복처리는 미검증이다.

'이 항목을 수첩으로 가져가기'를 누르자 WF24·drain·2026-10-30 초안이 채워지고 확인 후 추가하라는 안내가 보였다.
목록에추가 → 관리목록1개/마지막관리10-30/다음11-06을 확인했다.
'오늘 관리함' → 마지막관리11-01/다음11-08로 변경됐다.
이 시점에도 먼저받은파일내용이 그대로이고 DTSTART는11-06이었다. 수첩은 별개로 업데이트되며 로컬파일을 갱신하지 않는다.
본인 WF24 항목을 삭제해 관리목록0개를 확인했다. 제품기록은0개로 유지했다.
closeTab(page)를 호출했다. 마지막 Aside 로그가 'no current tabs' 뒤 동일URL의 다른탭을1개재표시하여,
다른에이전트탭 가능성 때문에 추가attach/닫기는 하지 않고 진행자에게 알렸다.

정리 / 현재 상태
평가용 전력2건과 관리1건은 UI삭제 후0개 확인. 다른 사용자기록 수정없음. 실제캘린더등록없음.
다운로드 파일은 실제 Aside 브라우저의 다운로드 경로에 생성됐다. 앱출력검증 용도이며 사용자다운로드 전체를 정리하지 않았다.
진행자가 최신본에 달력 동기화/재가져오기중복 안내와 전력하단가이드 문구를 좁게 수정 중이다.
아래 권고는 수정전 평가빌드에서의 관찰이며 새빌드문구확인은 진행자의 통합검증으로 남긴다.

권장 우선순위와 판정
P2 / 작은 수정: 전력 하단 가이드의 가구사용량 문구를 '기기 추가 전·미포함 가구 사용량'으로 일치시킨다.
P2 / 작은 수정: 달력 저장 근처에서 수첩 날짜수정은 기존 달력일정에 반영되지 않음,
재다운로드는 기존 일정을 갱신하지 않을 수 있으니 달력에서 중복·이전 일정을 확인하라고 안내한다.
P3 / 실제 재방문 과제 후 판단: 전력에 측정 시작·종료일과 환경 메모를 추가할 필요가 있는지 확인한다.
그래프만 추가하면 측정 조건의 차이를 설명하지 못하므로 먼저 조건 기록의 필요를 검증하는 것이 타당하다.
실제 캘린더 앱 가져오기·종일표시·중복처리·알림, 장기간 계량기 측정의 효과는 별도 운영 검증이다.
