# 귀뚜라미·경동나비엔 가스보일러 에러코드 행동 카드 원문 조사 — 2026-10-29

짝 데이터는 [boilers.json](./boilers.json)(38행)이다. 조사 범위와 원칙은 아래와 같다.

- **분석 단위**: 허브에 보이는 코드 1행이다. 기준은 빌드 `out/error-codes/{Kiturami,Navien}.html`(2026-10-29 13:07 빌드)의 `<h3 class="font-mono font-bold text-lg">`이다. 같은 번호라도 사이트가 제품군별로 나눈 행(귀뚜라미 10·98 각 2행)은 나뉜 그대로 둔다.
- **모집단**: 귀뚜라미 25행(두 자리 13 + AST 콘덴싱 12)과 나비엔 13행, 합계 38행이다. JSON 코드 목록과 h3 목록이 두 허브 모두 일치하는지 스크립트로 대조했다.
- **카드 판정 기준**: 리드가 정한 안전 원칙을 따른다. 사용자 조치는 제조사 자가진단 페이지나 사용설명서가 명시한 것만 넣는다. 가스 누설·연소(점화 실패 포함)·배기·과열·동결이 걸린 코드는 `contact`로 둔다. contact 카드에는 사용 중지, 가스 밸브·전원 차단(원문에 있을 때), 환기(원문에 있을 때), 서비스 연락만 쓴다. 분해·부품 조작(퇴수코크 열기, 호스 분리, 트랩 청소), 리셋 반복, 비눗물 누설 검사는 원문에 있어도 뺐다. 뺀 조치는 아래 「원문에 있으나 카드에서 뺀 조치」에 따로 적었다.
- **productLines 범위**: 사이트가 쓰는 제품군 6개(귀뚜라미)와 나비엔 가스보일러 가이드 범위만 적고 넓히지 않았다. 귀뚜라미 97은 예외로 거꾸로 IoT 콘덴싱을 넣었다. 6개 페이지 중 하나인 10762에 같은 97 조치가 있어서다.
- **데이터 시점**: 2026-10-29 KST에 내려받았다. 받은 파일은 `scratchpad/err-c/`(krb·navien·manuals·svc)에 두었고 저장소에는 넣지 않았다.

## 못 한 것·찾지 못한 것

- **나비엔의 「가스 냄새」 대처 원문: 찾지 못함.** 나비엔하우스 가스보일러 자가진단 가이드 67건의 제목을 브라우저(aside repl)로 전부 펼쳐 읽었다. 대조군으로 「CO(일산화탄소)감지기에서 소리가 나요」와 「배기가스(폐가스) 냄새가 나요」는 잡혔지만, 가스 냄새·누설 대처 가이드는 없었다. 나비엔 제품 사용설명서는 조사하지 않았다. 그래서 사이트 Er03의 「가스 냄새가 나면…」 문장은 근거 없음으로 기록한다(불일치 표 참고).
- **모델 번호: 옮기지 않음.** 두 제조사 모두 코드 원문이 제품군 단위다. 귀뚜라미 설명서 규격표와 표지에 용량 모델(예: AST 콘덴싱 대기개방식·대기차단식 용량별)이 있지만 이미지 PDF를 OCR로만 읽었다. 판독 신뢰도가 낮아 `models`에는 제품군만 적었다. 「모델 없음」이 아니라 「미검증」이다.
- **귀뚜라미 설명서 PDF URL: 고정 링크가 없다.** 다운로드 링크에 세션 값(`sid`)이 붙어 있어, 세션 쿠키 없이 요청하면 「잘못된 요청입니다」 HTML(42,230바이트)이 돌아왔다. 그래서 `manualUrl`은 자가진단 페이지로 두고, 설명서는 `manualLabel`에 다운로드 센터 경로와 `file_srl`로 적었다. 설명서 목록은 https://krb.co.kr/index.php?mid=download&category=7164 에 있다.
- **4번 타는 대기 차단식의 수동 물보충 절차(설명서 16쪽)는 읽지 않았다.** 95 카드는 「설명서 16쪽 참고, 확인 못 하면 서비스」로만 안내한다.
- 귀뚜라미 거꾸로IN·거꾸로IIHi·IN AD 설명서의 표지 모델 목록과 IoT 설명서 5쪽은 이미지를 직접 보지 않았다(OCR만).
- 사이트에 없는 코드는 범위 밖이라 카드를 만들지 않았다. 귀뚜라미 다른 제품군 17개 페이지, AST 설명서의 E626(불꽃소멸), 나비엔 Er01·Er17·밀폐식 Er02(E302) 등이 여기에 해당한다.

## 다른 제품군 페이지에서 본 것 (exploratory, 카드 범위 밖)

- krb.co.kr 가스보일러 자가진단 목록(category=185)에는 23개 제품군이 있고, 사이트는 그중 6개를 쓴다. 나머지 17개도 받아서 코드 뜻을 대조했다. 같은 번호의 뜻이 제품군마다 달랐다.
  - 98은 거꾸로 NEW콘덴싱(349)·거꾸로 콘덴싱(351)·거꾸로 하이핀(358)에서 「(버너·)배기과열안전장치 또는 지진감지센서」다.
  - 10은 저녹스(348)·NEW콘덴싱(349)·저녹스 AST(350)·트윈알파 N(355)에서 「배풍기 회전수」다.
  - 따라서 카드는 제품군을 좁혀 두어야 한다.
- 귀뚜라미 설명서 일부는 코드를 앞자리와 함께 표기한다. IN AD 설명서는 「E0 01」「E2 97」「E4 95」, IoT 설명서는 「E01」「E97」이다. 조절기 화면에 실제로 그렇게 뜨는지는 확인하지 못했다(불명).
- 4번 타는 설명서 29쪽의 96 행에는 자가진단 페이지에 없는 「지진감지센서가 작동된 상태입니다」가 함께 있다(OCR, 육안 미대조).
- 자가진단 10759의 E204~E234 송풍기 문구는 2026-10-29에도 그대로였다(사이트 주석의 9-16 관찰과 같다).

## 방법과 검증

- 귀뚜라미 자가진단은 `curl`(브라우저 UA)로 받아 `td.num`/`td.tit` 표를 파싱했다. 같은 페이지를 두 번 받아 원본 HTML 해시가 같은지 확인했다(359).
- 나비엔 가이드 15쪽은 `curl` 응답이 **HTTP 500**이었다. 응답에 본문 HTML이 없고, 본문은 RSC 페이로드(`bbscttPcCtnts`)에만 들어 있었다. 브라우저(aside repl)로 guide/306을 열어 제목 「[가스보일러] Er03, E3, E003이 표시돼요.」와 증상 설명 본문이 렌더되는 것을 확인했다. 즉 사용자 쪽 오류는 아니다. 같은 가이드를 두 번 받으면 원본 HTML 해시는 달랐고, 추출한 본문 해시는 같았다. 그래서 아래 표의 나비엔 해시는 **추출 본문 기준**이다.
- 귀뚜라미 설명서 7권은 이미지 PDF다(`pdftotext` 결과가 쪽당 1자). PNG(110dpi)로 렌더한 뒤 macOS Vision OCR(ko-KR)로 읽었다. 카드 판단에 쓴 쪽 가운데 19621 25·26쪽, 14141 28쪽, 14582 27쪽, 14107 11쪽은 이미지를 직접 보고 대조했다.
- 인용 검증: JSON `quotes` 중 자가진단·가이드 원문 69건을 추출 텍스트와 공백 무시 부분일치로 대조했고, 불일치는 0건이었다. 대조군으로 원문에 없는 문장(「가스 냄새가 나면 재가동하지 마세요」)은 불일치로 잡혔고, 원문에 있는 문장은 일치로 잡혔다. 설명서 인용은 OCR이라 이 대조에 넣지 않았고, 각 인용의 `where`에 「육안 대조」 또는 「OCR 판독」을 적었다.
- 사이트 대조: JSON의 hub별 코드 목록이 `out/error-codes/*.html` h3 목록과 같은지 확인했다(Kiturami 25, Navien 13 일치).
